## 标题

把 PySide6 桌面软件做到 beta，第一次被 798MB 安装包教育了

## 正文

做独立开发大概 14 天的时候，
我做完了 V1.1-beta 的所有功能：

- 模板排版（选择 → 填写 → 预览 → 导出）
- 深浅色主题切换
- PDF 合并 / 拆分 / 压缩 / 转换
- 打包为单文件可执行程序

跑通功能那一刻，我以为这一版要"完结"了。

然后我跑了一遍 PyInstaller。

输出文件大小：**798MB**。

---

### 第一反应：是不是配置错了？

我以为是 spec 文件里有什么 hidden import 被多打了。
检查了一遍，没看到明显问题。
又以为是图标、字体、或者样例 PDF 被打进去了，
逐项排除后，体积纹丝不动。

后来才意识到：

**不是我代码胖，是 PySide6 胖。**

一个空壳 PySide6 + Qt 的 hello world 窗口，
`--onefile` 打包出来 200MB+。
加上我们用到的 QtWebEngine（早期版本评估用过的）、
PDF 字体集、SQLite 驱动、SVG 渲染模块……

加起来 798MB，是 PySide6 工程的**正常水位**。

不是 bug。
是**桌面软件发布这条赛道本身就是工程**。

---

### 我以前没想清楚的事

以前我做 Web 项目，
"完成"的标准很清楚：
能跑、API 正常、能部署、监控接上。

但桌面软件不一样。

完成 = 功能 ✓
+ 安装包体积 ≤ 150MB（我们的红线）
+ 冷启动 ≤ 5s
+ 跨 Windows 10/11 可装
+ 不带 VC++ 运行库依赖 / 带正确提示
+ 卸载干净
+ 主题在用户系统下不崩
+ 日志可定位崩溃

这一串，**功能完成的那一刻是 0 分**。
发布那一刻才是 100 分。
中间这一段，过去我以为是"打包配置"，
实际是"产品工程"。

---

### 当前我们 V1.1-beta 的状态

- 功能完成度：100%
- 安装包体积：798MB（**未达标**）
- 已定的瘦身方向：剥离 WebEngine / 拆分多模块按需加载 / 改 --onedir / 字体子集化
- 目标：≤150MB（总章程红线）
- 预计 V1.1 正式版发布时间：2-3 周内

V1.1-beta 暂不公开下载，先把体积压下来再说。

---

### 反思

写代码的爽感是即时的，
打包的挫败感也是即时的。

但这两件事之间的差距，
可能比"从 0 到 1"还大。

如果你也在做 Python 桌面软件，
欢迎交流你们项目目前最大的体积来自哪里：
- PySide6 本身
- 字体
- ffmpeg / opencv 类依赖
- 打包模式选错
- 其他

我准备这一两周把瘦身过程单独发一篇，
先看哪条路最有效。
