## 第八部分：代码安全与质量保障规范

### 8.1 代码保护与反编译防护
- 打包发布前，必须使用 `pyarmor` 或 `cython` 对核心业务逻辑代码进行混淆或编译
- 敏感配置信息（API Key、密钥等）不得硬编码在源码中，必须通过环境变量或加密配置文件读取
- 禁止在日志或错误提示中输出敏感信息（如文件路径、密钥片段）

### 8.2 第三方依赖安全管理
- 每次新增或更新第三方库后，必须执行漏洞扫描：`pip-audit` 或 `safety check`
- 关键依赖（PyMuPDF、pypdf、PySide6）必须保持最新稳定版本
- 禁止引入未经社区验证的冷门依赖包（GitHub Stars < 100 或超过6个月未更新）
- 定期（至少每月一次）执行全项目依赖扫描：`pip-audit -r requirements.txt`

### 8.3 文件处理安全规范
- 所有 PDF 文件读写操作必须包裹在 `try...except` 异常捕获块中
- 用户上传的文件必须校验扩展名白名单（如 `.pdf`, `.png`, `.jpg`, `.docx`）
- 禁止以 root/管理员权限执行文件处理逻辑
- 文件处理超时机制：单个文件处理超过 60 秒应自动中止并提示用户

### 8.4 AI 生成代码审查规则
- AI 生成的代码在合入项目前，必须满足以下条件：
  1. 通过 `pip-audit` 扫描，无高危漏洞
  2. 与《总章程》和《DESIGN.md》规范无冲突
  3. 每个新函数必须有对应的单元测试或手动验证记录
  4. 禁止 AI 自行安装或升级第三方依赖包
  5. 所有用户输入必须经过基本格式校验
- AI 生成的代码必须保留清晰的注释，标注"AI 生成，已审查"及审查日期

### 8.5 安全审查工具与使用场景

| 工具 | 用途 | 使用场景 |
| :--- | :--- | :--- |
| `pip-audit` | 扫描第三方依赖已知漏洞 | 每次新增依赖 / 每月定期 |
| `slopscan` | 检测 AI 生成代码的常见安全漏洞（含 AI 特征检测） | 每个功能模块开发完成后 |
| `A3` 或 `Sandyaa` | 深度安全审计，自动验证漏洞真实性 | V1.0 发布前 / 大版本更新前 |
| `bandit` | Python 代码静态安全分析 | 日常开发中随时使用 |
| `safety` | 商业级依赖漏洞扫描 | 与 `pip-audit` 互补使用 |

### 8.6 安全审查执行频率

| 审查级别 | 执行时机 | 负责工具 |
| :--- | :--- | :--- |
| **日常审查** | 每次 AI 生成代码后 | QClaw / CodeBuddy 基础审查 |
| **模块审查** | 每个功能模块开发完成后 | QClaw + slopscan 深度扫描 |
| **发布审查** | V1.0 打包发布前 | QClaw + A3/Sandyaa + pip-audit 全项目审计 |
| **定期审查** | 每月一次 | pip-audit 依赖扫描 |

### 8.7 自动化测试与回归验证
- 每次代码变更后，必须执行核心功能手动回归测试，至少覆盖：
  - 合并拆分：多文件合并、按页拆分
  - 水印处理：文字/图片水印导出效果
  - 格式转换：PDF↔图片转换质量
- 鼓励使用 `pytest-qt` 编写自动化 UI 测试，逐步减少手动测试负担
- 测试用例应覆盖正常场景和异常场景（空文件、超大文件、非标准格式）

### 8.8 安全事件响应规则
- 发现安全漏洞后，必须在 24 小时内评估影响范围并制定修复计划
- 修复后必须在版本更新日志中明确记录漏洞编号和修复内容
- 所有安全变更必须走 PM Agent → 开发 Agent → PM 审查 → 负责人确认的标准流程

### 8.9 安全操作指令模板

#### 日常审查指令
> "请对我刚才生成的代码进行安全审查，重点检查：1. 是否存在未捕获的异常；2. 是否存在硬编码的敏感信息；3. 用户输入是否做了基本的格式校验。只输出审查结果，不修改代码。"

#### 模块审查指令
> "请帮我安装并执行 slopscan 对 `pages/` 目录进行安全扫描。命令：`pip install slopscan && slopscan pages/ --ai-detection`。扫描完成后，将发现的漏洞按严重程度分类列出，并给出修复建议。不要直接修改代码，先输出报告让我确认。"

#### 发布审查指令
> "请帮我执行以下发布前安全检查：1. `pip-audit` 扫描全部依赖；2. `bandit` 扫描项目源码；3. 将所有扫描结果汇总为安全审计报告，保存到 `04-项目文档/安全审计报告_V1.0.md`。"

### 9.1 主要竞品：PDFgear
- **定位**：大众全能型PDF工具，全平台覆盖，AI驱动，完全免费

- **不拼功能广度，拼设计师专属深度**
- **转换目标**：不仅"还原"，更要"优化"——自动修正列宽、清除冗余格式、匹配设计师交付标准
- **模板系统**：从"填空工具"升级为"版式编辑器"，开放设计控制权
- **隐私安全**：纯本地处理，无需联网，这是PDFgear无法完全承诺的
