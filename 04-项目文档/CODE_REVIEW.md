# 印流PDflow AI Code Review 规则体系

> **版本:** V1.0  
> **生效日期:** 2026-05-12  
> **适用范围:** 所有 AI 助手（PM Agent、开发 Agent）参与的代码变更  
> **强制级别:** 每次代码提交/合并前必须执行

---

## 一、审查总则

### 1.1 审查触发时机

| 场景 | 是否触发审查 | 说明 |
| :--- | :--- | :--- |
| 新增功能页面（`xxx_page.py/.ui`） | ✅ 强制 | 完整审查 |
| 修改现有页面逻辑 | ✅ 强制 | 完整审查 |
| 修改 `common/` 公共模块 | ✅ 强制 | 完整审查 |
| 修改 `global.qss` 样式 | ✅ 强制 | UI/UX 专项审查 |
| 修改 `run_main.py` 入口 | ✅ 强制 | 完整审查 |
| 修改总章程/DESIGN.md | ⚠️ 需人工确认 | AI 不可私自修改 |
| 修改 `04-项目文档/backups/` | ❌ 不触发 | 备份目录 |
| 修改 `_旧版归档/` | ❌ 禁止 | AI 禁止修改 |

### 1.2 审查执行者

| 角色 | 职责 |
| :--- | :--- |
| **PM Agent** | 项目合规性、文档一致性、业务逻辑验收标准核对 |
| **开发 Agent** | 代码实现层面的自查（性能、安全、边界处理） |
| **用户（项目负责人）** | 最终决策权，所有「需要人工确认」级别问题必须由用户确认 |

### 1.3 审查证据要求

AI 进行代码审查时，**必须提供证据**，不能仅给出结论。证据形式包括：
- 代码引用：`[文件名](file:///路径#L行号)`
- 设计文档引用：`[DESIGN.md](file:///路径#章节)`
- 对比说明：修改前 vs 修改后的差异

## 二、审查维度与检查清单

### 2.1 项目合规性 (Compliance)

**审查目标：** 代码是否符合《项目总章程 V2.3》的所有技术栈和架构约束

#### 检查清单

| # | 检查项 | 判断标准 | 违规示例 |
| :--- | :--- | :--- | :--- |
| C-01 | 框架使用 | 必须使用 `PySide6`（Qt 6.11+） | `import flet`、`ft.*` 组件 |
| C-02 | 入口文件 | 必须是 `run_main.py` | 直接运行 `xxx_page.py`、使用 `main_flet.py` |
| C-03 | UI 文件格式 | 必须是 `.ui`（Qt Designer 可编辑）+ 编译后的 `Ui_*` 类 | 纯代码手写 UI、使用 Flet 组件 |
| C-04 | 页面位置 | 必须在 `pages/` 目录 | 放在 `src/`、`common/` 或其他目录 |
| C-05 | 样式系统 | 必须使用 QSS + `pages/global.qss` | 使用 Tkinter 样式、内联样式字符串 |
| C-06 | 文件选择器 | 必须使用 `QFileDialog` | 使用 `ft.FilePicker`、`TkFilePicker` |
| C-07 | PDF 处理 | 必须通过 `common/pdf_api.py` | 直接调用 `fitz.open()` 而不经过封装 |
| C-08 | 旧版归档 | 禁止引用 `_旧版归档/` 代码 | `from _旧版归档 import ...` |
| C-09 | LOGO 使用 | 必须使用 `02-素材资源/` 中的现有 LOGO | AI 生成、设计、修改 LOGO |

**违规处理：** 发现 C-01 ~ C-09 任何一项违规，审查结果直接判定为 **必须修复**，不得降级。

#### 审查报告格式

```markdown
### 项目合规性审查结果

| 检查项 | 状态 | 证据 |
| :--- | :--- | :--- |
| C-01 框架使用 | ✅/❌ | [run_main.py#L22](file:///.../run_main.py#L22) 使用 `from PySide6.QtWidgets import ...` |
| C-02 入口文件 | ✅/❌ | 入口为 `run_main.py` |
| ... | ... | ... |

**结论：** 通过 / 不通过（发现 X 项违规）
```

### 2.2 文档一致性 (Documentation)

**审查目标：** 新增或修改的功能，是否同步更新了相关文档

#### 检查清单

| # | 检查项 | 判断标准 |
| :--- | :--- | :--- |
| D-01 | 总章程同步 | 新增功能模块是否更新了《项目总章程》的「功能模块表」和「架构关系」 |
| D-02 | 设计规范同步 | UI 变更是否更新了 `DESIGN.md`（新增组件、修改配色等） |
| D-03 | PM Agent 检查 | PM Agent 出具开发指令后，是否检查了需要同步更新的文档清单 |
| D-04 | 版本记录 | 《项目总章程》的「版本变更记录」是否同步更新 |
| D-05 | AI 禁止私自修改 | AI 不可私自修改总章程/DESIGN.md，必须经用户确认 |

**特殊规则：**
- 开发 Agent **只能提议** 需要同步更新的文档，**不能直接修改**
- 所有文档变更必须由用户确认后，由 PM Agent 或用户本人执行

#### 审查报告格式

```markdown
### 文档一致性审查结果

| 检查项 | 状态 | 说明 |
| :--- | :--- | :--- |
| D-01 总章程同步 | ✅/❌/⏸️ | 需要同步更新「功能模块表」中的 XXX 模块 |
| D-02 设计规范同步 | ✅/❌/⏸️ | 无 UI 变更，无需更新 |
| ... | ... | ... |

**待确认项：**
- [ ] 需要同步更新《项目总章程》的 XXX 章节
- [ ] 需要同步更新 DESIGN.md 的 XXX 章节

**结论：** 需要同步更新 X 份文档
```

### 2.3 业务逻辑与边界处理 (Logic & Edge Cases)

**审查目标：** 核心功能的逻辑正确性，以及异常情况的容错处理

#### 检查清单

| # | 检查项 | 判断标准 | 覆盖范围 |
| :--- | :--- | :--- | :--- |
| L-01 | 核心功能正确性 | 水印透明度、合并拆分、PDF 导出等核心逻辑是否符合预期 | 水印、合并、压缩、转换 |
| L-02 | 空文件处理 | 输入文件为空时，是否有明确的错误提示 | 所有文件输入场景 |
| L-03 | 非 PDF 格式处理 | 输入非 PDF 文件时，是否有格式校验和提示 | 所有 PDF 处理场景 |
| L-04 | 超大文件处理 | 输入超大文件时，是否有内存/性能保护措施 | 所有文件处理场景 |
| L-05 | 路径不存在处理 | 文件路径不存在时，是否有 `os.path.exists()` 校验 | 所有文件读写场景 |
| L-06 | 异常捕获 | 是否有 `try...except` 捕获并友好提示用户 | 所有外部 API 调用 |
| L-07 | 输出文件冲突 | 输出文件已存在时，是否有覆盖确认或自动命名 | 所有文件输出场景 |

#### 审查报告格式

```markdown

| :--- | :--- | :--- |

| L-02 空文件处理 | ✅/❌ | [compress_page.py#L32](file:///.../compress_page.py#L32) 有 `if not file_path: return` 校验 |
| ... | ... | ... |

**发现的问题：**
1. ❌ L-04 超大文件处理：未限制最大文件大小，可能导致内存溢出
2. ❌ L-07 输出文件冲突：未检查输出文件是否已存在
```

### 2.5 性能与安全性 (Performance & Security)

**审查目标：** 代码是否有基本的性能优化，以及敏感信息的安全性

#### 检查清单

| # | 检查项 | 判断标准 |
| :--- | :--- | :--- |
| P-01 | 循环性能 | 循环处理大量数据时，是否有分批/异步处理机制 |
| P-02 | 文件操作性能 | 大文件读写是否使用缓冲、避免全量加载到内存 |
| P-03 | 内存泄漏风险 | 是否有未关闭的文件句柄、未释放的 Qt 对象 |
| P-04 | 敏感信息硬编码 | 是否有硬编码的文件路径、API 密钥、密码等 |
| P-05 | 路径遍历攻击 | 用户输入的路径是否经过校验，防止 `../../` 越权访问 |
| P-06 | 异常信息泄露 | 异常提示是否泄露系统路径、堆栈信息等敏感内容 |
| P-07 | Qt 对象生命周期 | 是否正确管理 Qt 对象的父子关系，避免野指针 |

#### 审查报告格式

```markdown
| P-04 敏感信息硬编码 | ✅/❌ | 未发现硬编码路径/密钥 |
| ... | ... | ... |

**发现的问题：**
1. ❌ P-03 内存泄漏风险：[xxx_page.py#L89](file:///.../xxx_page.py#L89) 文件句柄未关闭
2. ⚠️ P-06 异常信息泄露：异常提示中包含完整文件路径

**结论：** 通过 / 不通过（发现 X 项问题）
```

## 三、审查结果分级

每次审查后，必须将发现的问题按以下等级分类：

| 等级 | 图标 | 含义 | 处理方式 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| **必须修复** | 🔴 | 阻塞性问题，不修复不得合并 | 立即修复，重新审查 | 使用 Flet 框架、违反总章程红线 |
| **建议修复** | 🟡 | 重要但非阻塞，影响用户体验或性能 | 尽快修复，可在下一版本 | 按钮高度不符合 DESIGN.md、异常提示泄露路径 |
| **需要人工确认** | 🟠 | AI 无法独立判断，需用户决策 | 提交用户确认后再继续 | 新增功能模块、修改总章程、设计方向变更 |
| **可忽略** | 🟢 | 轻微问题或合理偏离，不影响质量和规范 | 记录但无需修复 | 注释格式不统一、变量命名风格差异 |

### 3.1 降级规则

| 规则 | 说明 |
| :--- | :--- |
| 🔴 不得降级 | 「必须修复」级别问题**不得降级为「建议修复」**，必须由用户确认后方可降级 |
| 🟡 可降级 | 「建议修复」可降级为「可忽略」，需说明理由 |
| 🟠 不可越权 | 「需要人工确认」AI 不可自行决策，必须提交用户 |

### 3.2 审查通过标准

| 条件 | 是否允许通过 |
| :--- | :--- |
| 存在 🔴 必须修复 | ❌ 不得通过 |
| 存在 🟡 建议修复 | ✅ 可通过，但须列出修复计划 |
| 存在 🟠 需要人工确认 | ⏸️ 暂停，等待用户确认 |
| 仅有 🟢 可忽略 | ✅ 通过 |
| 无任何问题 | ✅ 通过 |

## 四、审查流程

### 4.1 标准审查流程

```
用户提出需求
  ↓
PM Agent 出具开发指令（含文档同步清单）
  ↓
开发 Agent 执行开发
  ↓
开发 Agent 完成自查（2.3 业务逻辑、2.5 性能安全）
  ↓
PM Agent 执行完整审查（2.1~2.5 全维度）
  ↓
生成审查报告（分级 + 证据）
  ↓
是否有 🔴 必须修复？ ──是──→ 返回修复 → 重新审查
  ↓ 否
是否有 🟠 需要人工确认？ ──是──→ 提交用户确认 → 根据确认结果继续
  ↓ 否
审查通过 → 提交用户验收
```

### 4.2 快速审查流程（小改动）

适用于：样式微调、文字修改、注释补充

```
开发 Agent 执行修改
  ↓
PM Agent 执行 2.1 项目合规性 + 2.4 UI/UX 审查
  ↓
生成轻量审查报告
  ↓
是否有 🔴 或 🟠？ ──是──→ 转入标准流程
  ↓ 否
通过 → 提交用户验收
```

## 六、附录：常见问题与处理指引

### 6.1 技术栈冲突

**问题：** 代码中出现 `import flet` 或 `ft.*` 组件  
**处理：** 🔴 必须修复。替换为对应的 PySide6 组件。  
**参考：** [run_main.py](file:///F:/印流PDflow项目/run_main.py)、[项目总章程 V2.3 第四部分](file:///F:/印流PDflow项目/04-项目文档/印流PDflow_项目总章程_V2.3.md)

### 6.2 配色不符

**问题：** 使用了非 DESIGN.md 定义的颜色  
**处理：** 🟡 建议修复。替换为 DESIGN.md 中定义的标准色值。  
**参考：** [DESIGN.md 第二部分](file:///F:/印流PDflow项目/04-项目文档/DESIGN.md)  
**注意：** 项目总章程 V2.3 第五部分的配色与 DESIGN.md 存在细微差异（如页面背景 `#0B0E11` vs `#0A0A0F`）。**以 DESIGN.md 为准**，因为它是完整的 UI 设计规范。

### 6.3 文档未同步

**问题：** 新增功能未更新总章程或 DESIGN.md  
**处理：** 🟠 需要人工确认。PM Agent 列出需要同步的文档清单，提交用户确认后更新。

### 6.4 边界处理缺失

**问题：** 未处理空文件、非 PDF 格式、超大文件等异常情况  
**处理：** 🔴 必须修复。补充相应的校验和错误提示。

### 6.5 敏感信息泄露

**问题：** 异常提示中包含完整文件路径或系统信息  
**处理：** 🟡 建议修复。改为友好提示，如「文件读取失败，请检查文件是否被占用」。
