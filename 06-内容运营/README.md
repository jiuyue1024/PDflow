# 内容运营工作流（V1）

> 每天 5 分钟，持续输出。
> 70% 过程 + 20% 结果 + 10% 产品链接

---

## 第一步：建立内容素材库（每天 5 分钟）

每天打开 `marketing/changelog.md`，回答三个问题：

1. **今天修了什么？**
2. **今天发现什么问题？**
3. **今天为什么这样改？**

记录够 3-5 条，就可以生成一篇帖子。

### 素材库结构

```
marketing/
├── ideas.md           # 内容灵感收集（想到就丢进来）
├── users.md           # 用户故事 & 反馈（案例帖素材）
├── changelog.md       # 开发日志（每天 5 分钟，帖子从这里生成）
├── screenshots/       # 截图素材采集
│   ├── 采集清单.md     # 截图管理清单
│   └── post_xxx/      # 按帖子归类的截图
└── posts/             # 帖子成品
    ├── template.md    # 帖子创建模板（新建时复制）
    ├── post_001.md    # 第一帖：问题发现篇
    └── post_002.md    # 第二帖：问题解决篇
```

---

## 第二步：选定帖子类型

不要只发"发布了"。固定三类帖子，轮流输出。

| 类型 | 推荐度 | 适合场景 | 结构 | 目的 |
| :--- | :--- | :--- | :--- | :--- |
| **开发日志** | ⭐⭐⭐ 推荐 | 日常进度、技术优化 | 背景 → 问题 → 定位 → 结果 → 反思 | 互动讨论 |
| **案例帖** | ⭐⭐⭐ 最高优先级 | 用户故事、使用场景 | 原流程 → 痛点 → 解决 → 结果 → 耗时 | 证明价值 |
| **失败复盘** | ⭐⭐⭐ 最容易有人看 | 踩坑经历、翻车现场 | 为什么改 → 哪里翻车 → 怎么救 → 学到了什么 | 引发共鸣 |

## 第三步：一帖多发（30 分钟）

### 工作流

1. 在 `marketing/posts/` 下写好完整版（或复制 `template.md`）
2. 按平台拆到 `drafts/` 目录
3. 各平台适配格式后发布

### 平台适配

| 平台 | 风格 | 长度 | 目录 |
| :--- | :--- | :--- | :--- |
| 小红书 | 短平快、带表情 | 300-500 字 | `drafts/xiaohongshu/` |
| Nodeloc | 技术细节、代码片段 | 500-800 字 | `drafts/nodeloc/` |
| 微信公众号 | 故事感、情绪共鸣 | 1500-2000 字 | `drafts/wechat/` |
| GitHub Discussion | 简洁英文 | 200-400 字 | `drafts/github/` |

### 内容比例

```
70% 过程  +  20% 结果  +  10% 产品链接
```

### 红线

- ❌ 下载地址不放第一句
- ❌ 不堆砌技术参数
- ❌ 不剧透未来版本细节
- ❌ 不喊口号（"颠覆"、"革命"等禁用）
- ❌ 不暴露后端实现细节

---

## 发帖节奏建议

| 阶段 | 频率 | 内容 |
| :--- | :--- | :--- |
| 启动期（第 1-2 周） | 每周 2-3 帖 | 开发日志为主，积累关注 |
| 稳定期（第 3-4 周） | 每周 2 帖 | 开发日志 + 案例帖交替 |
| V1.1 发布期 | 发布前 1 周密集输出 | 开发日志 + 失败复盘 + 发布预告 |
| V1.1 发布后 | 每周 1-2 帖 | 案例帖为主 + 用户反馈互动 |
